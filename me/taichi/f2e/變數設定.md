# 指令碼屬性(環境變數)設定清單

> 這份文件是**自足的**——新開一個對話直接讀這裡就能接手。

## 先看這一條:設定的位置,不是你想的那樹

GAS 的 Script Properties(指令碼屬性)是**不共用資源**——library 專案跟使用它的專案,各自有各自獨立的一份,**不會互通**。

**代表:一個 library 程式碼裡讀到的指令碼屬性,要設定在「這個 library 自己的 GAS 專案」上,不是設定在呼叫它的主專案上。**

`library/jira-identity-lib`、`library/notify-env-lib` 兩份 README.md 目前寫的是「放在使用這個 library 的主專案的指令碼屬性」——**這句話是錯的**,跟實際運作方式相反,還沒修正,見文件底下的待辦。

> Source: [Libraries | Apps Script | Google for Developers](https://developers.google.com/apps-script/guides/libraries) ——「Script Properties 是 not-shared resource,library 跟使用它的專案只能各自存取自己那一份」。

## 各專案要設定的指令碼屬性

### `library/jira-identity-lib`(Jira 認證,library 自己的專案上設定)

全部都是**必填**,沒設會拋錯。

| Key | 說明 |
|---|---|
| `JIRA_URL` | Jira 網域(例如 `https://104corp.atlassian.net`),全體共用 |
| `JIRA_EMAIL` | 部長帳號的 email |
| `JIRA_TOKEN` | 部長帳號的 API token |
| `JIRA_EMAIL_OCEAN` | 課長(Ocean)email,`getAdminLead()` 用 |
| `JIRA_TOKEN_OCEAN` | 課長(Ocean)token |
| `JIRA_EMAIL_AGNES` / `JIRA_TOKEN_AGNES` | AGNES 的 email / token |
| `JIRA_EMAIL_BRIAN` / `JIRA_TOKEN_BRIAN` | BRIAN 的 email / token |
| `JIRA_EMAIL_ENYA` / `JIRA_TOKEN_ENYA` | ENYA 的 email / token |
| `JIRA_EMAIL_JUNE` / `JIRA_TOKEN_JUNE` | JUNE 的 email / token |
| `JIRA_EMAIL_PEDRO` / `JIRA_TOKEN_PEDRO` | PEDRO 的 email / token |
| `JIRA_EMAIL_SAMURA` / `JIRA_TOKEN_SAMURA` | SAMURA 的 email / token |
| `JIRA_EMAIL_STEVEN` / `JIRA_TOKEN_STEVEN` | STEVEN 的 email / token |
| `JIRA_EMAIL_WILLIAM` / `JIRA_TOKEN_WILLIAM` | WILLIAM 的 email / token |

共 21 個 key。`JIRA_EMAIL_OCEAN`/`JIRA_TOKEN_OCEAN` 同時服務「課長」跟「使用者 OCEAN」兩種呼叫方式,只需要設定一次。

### `library/notify-env-lib`(通知設定,library 自己的專案上設定)

| Key | 必填 | 說明 |
|---|---|---|
| `JIRA_MESSAGE_WEBHOOK_URL` | 選填 | Jira 相關通知要送到的 Google Chat webhook URL |

### `library/notify-lib`

不需要設定任何指令碼屬性——`ChatNotifier`/`Notifier` 的 webhook URL 是呼叫端傳參數進來的,不是自己讀指令碼屬性。

唯一有 `getProperty` 的地方是 `testChatNotifier.js` 這個獨立的手動測試檔案,用 `CHAT_DEVLOP_WEBHOOK_URL`(選填,沒設定就跳過),跟正式程式碼路徑無關。

### `library/infra-lib`

不需要設定任何指令碼屬性——`DriveClient`/`FormClient`/`SheetClient` 完全不碰 `PropertiesService`。

### `scrum/retrospective`(主專案,設定在自己的專案上)

| Key | 必填 | 說明 |
|---|---|---|
| `RETRO_CHAT_WEBHOOK_URL` | 用到個人頻道通知才會拋錯 | 個人 Google Chat webhook——「已建立」「已發布」通知、失敗警示都用這個 |
| `B_TEAM_RETRO_WEBHOOK` | 用到團隊頻道通知才會拋錯 | 團隊 Google Chat webhook——「提醒填寫問卷」用這個 |

### `jira/quarterly-tickets`(主專案)

**自己不用設定任何指令碼屬性**——全部透過 `JiraIdentityLib`、`NotifyEnvLib` 兩個 library 取得,那兩份要設定在 library 自己的專案上(見上面)。

### `jira/worklog-migrate`(主專案)

**自己不用設定任何指令碼屬性**——全部透過 `JiraIdentityLib` 取得。

### `bug-triage`(主專案,獨立一套,沒有用 jira-identity-lib)

| Key | 必填 | 說明 |
|---|---|---|
| `WEBHOOK_TOKEN` | 是(沒對上會被拒絕) | 驗證 Power Automate/Teams 打進來的 webhook 是不是合法呼叫 |
| `JIRA_URL` | 是 | Jira 網域 |
| `JIRA_EMAIL` | 是 | 這個專案自己的 Jira 帳號 email(只有單一身份,沒有分課長/使用者) |
| `JIRA_TOKEN` | 是 | 對應的 API token |
| `OPENAI_API_KEY` | 是 | 呼叫 OpenAI 幫忙評分/分類用的 API key |
